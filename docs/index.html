OpenBot
为什么本地 三步开始 API 实测证据 复刻声明
本地优先 · MIT 开源 · 数据不出本机

你的 AI Agent，跑在你自己机器上

OpenBot 是一个本地优先的 agent 运行时。一条命令起服务，暴露一个极小的事件 API， 用 SSE 把 agent 的思考与动作流式推给你的客户端。渠道、会话、agent、插件与配置， 全部落在本机的 ~/.openbot。

Node ≥ 20.12 本地端口 4132 事件 API + SSE MIT License CI 已实测
三步开始 → 查看 API GitHub 仓库

本页是静态说明页。OpenBot 不是在线应用——它必须在你自己的机器上运行。

Why Local

为什么必须是本地优先

把 agent 放在云端，你就要把文件、上下文和凭据一起交出去。OpenBot 反过来做：运行时在你机器上，模型调用由你自己的密钥发起。

数据不出本机

渠道、会话、消息与插件状态存放在 ~/.openbot，不上传任何托管服务。

自己的密钥

通过 AI SDK 直连 Anthropic / Google / OpenAI，密钥留在本机环境变量里。

可插拔 Agent

从 ~/.openbot/agents/<id>/AGENT.md 载入自定义 agent，无需改动运行时。

Quick Start

三步，把它跑起来

需要 Node ≥ 20.12。整个过程不依赖任何托管服务。

克隆

把仓库拉到本地。

git clone …/openbot.git

安装与构建

用 pnpm 装依赖并编译 TypeScript。

pnpm install && pnpm build

启动

服务监听 4132，浏览器或 curl 均可访问。

pnpm start

API Surface

极小的事件 API

运行时不暴露庞大的 REST 面，只给四个入口。客户端订阅 SSE，把事件发回去即可驱动 agent。

端点方法用途
/api/healthGET健康检查，返回运行时状态、版本与 apiVersion
/api/eventsGETSSE 流：订阅 agent 的思考、工具调用与结果事件
/api/publishPOST发布事件以驱动 agent（需 channelId，请求体经 zod 校验）
/api/stateGET读取运行时状态（渠道 / 会话 / agent / 插件）
内置两个 agent：system 走 LLM 运行时并带存储工具； state 是确定性的存储读取 agent，不需要任何模型密钥——适合做冒烟测试与自动化校验。
Evidence

实测证据，不是「应该能跑」

每次 push 都会在 GitHub Actions 的 Node 22 runner 上执行：装依赖 → 构建 → 起服务 → 打真实 HTTP 请求并断言状态码。

# GET /api/health HTTP 200 {"status":"ok","version":"0.5.3","apiVersion":1} # GET /api/state HTTP 200 # POST /api/publish （故意发非法请求体） HTTP 400 {"error":"Invalid publish event payload", "details":["Invalid input: expected string, received undefined"]} HEALTH_200=ok STATE_200=ok PUBLISH_VALIDATION_400=ok

通过
pnpm install

通过
产出 dist/app/cli.js

起服务并打 API

通过
4132 返回真实 HTTP 响应

为什么 /api/publish 返回 400 反而是正证据：它证明路由与 zod 校验层真的在工作。 如果只是端口开着，这里会是超时，而不是一条结构化的校验错误。
每次 push 都会触发这轮验证。完整的终端日志可在仓库 Actions 页对应运行中查看， 服务端日志也可从 Artifacts 下载。
